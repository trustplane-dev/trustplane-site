Why now

Machines still log in like it's 2010 — with a long-lived shared secret.

A key is a bearer secret.Whoever holds the string is the client — copyable, replayable, and valid from anywhere until someone rotates it. Agents multiply how many of these exist.
A key is not bound to the request.A token that can read /orders can be replayed against /admin/delete-everything if the server forgets to check. It proves who, never what this specific request is allowed to do.
Audit needs request-level evidence.Reviews ask the same things: what called what, why was it allowed, which policy applied, and how fast can we revoke it?
The idea

Prove the request. Don't present a secret.

A caller gets a short-lived, audience-scoped passport from the identity it already has, then attaches proof bound to this exact request. A local verifier checks it — and only then lets the request through.

FAQ

Answers for security and platform teams.

How do you authorize AI agents that call APIs and tools?

Give each agent a short-lived, audience-scoped passport instead of a long-lived API key, and have it attach transcript-v1 proof that binds the exact request. A local TrustPlane Auth verifier checks the proof and allows or denies the call before it reaches the tool or API — so a leaked credential cannot be replayed against a different request.

Is this an alternative to API keys for machine-to-machine access?

Yes. TrustPlane Auth replaces long-lived keys and static bearer tokens with proof-bound authorization: a caller proves one specific request rather than presenting a reusable secret. The proof is bound to the request and consumed once, so it cannot be copied and reused from elsewhere.

Does it replace OAuth, IAM, or a service mesh?

No. It adds request-bound, short-lived, proof-bound authorization on top of the workload identity you already have (SPIFFE/SPIRE, OIDC/JWT, or a local issuer). Your application still owns business authorization such as tenants, roles, and resources.

Do I need Kubernetes or a hosted service?

No. TrustPlane Auth is Kubernetes-compatible but not Kubernetes-required, and it works locally and offline with no account, database, or hosted bundle source. SPIFFE/SPIRE is a recommended production identity integration on Kubernetes, but it is optional.

What stops a stolen passport from being replayed?

Four things compound: short expiry, audience and route scoping, transcript-v1 request binding (so it only works for the exact request), and atomic replay consume (the jti is one-time).

Is it open source, and how do I start?

Yes — it is open source. Start from the documentation and the GitHub organization, which includes caller-side SDKs for Go and Node.js (TypeScript).
