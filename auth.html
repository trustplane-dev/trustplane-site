TrustPlane Auth

Proof-bound authorization where machine traffic enters.

TrustPlane Auth runs near your protected APIs, tools, and services. It verifies a short-lived passport plus per-request proof, applies local policy, denies unsafe calls before the upstream runs, and emits decision evidence. Open source, local, and offline — no mandatory phone-home.

Runtime job

Make the boundary smart enough to say no.

A machine caller should not get a free pass because it holds a token-shaped string. Auth rebuilds the request transcript and checks identity, audience, request binding, policy, freshness, and replay state before forwarding traffic.

Capabilities

What Auth ships today.

Passports

Issue & verify

Mint and locally verify a short-lived, audience-scoped, proof-bound passport derived from an existing workload identity.

Request binding

transcript-v1

Bind a passport to this exact request — method, path, body hash, audience, route, and a nonce/time bucket.

Replay protection

One-time jti

Consume each proof once, atomically, with in-memory or Redis-backed shared replay state for multi-replica deployments.

Bundle policy

Per-route rules + freshness

Authorize by route and source with fail-closed staleness handling, all evaluated from a local bundle.

Signed bundles

Trust you can verify

Build, sign, verify, refresh, and remove trust and policy material; production loading rejects unsigned or tampered bundles.

Trust anchors

Add a client, no redeploy

Authorize many issuers and clients per route; add a new client by publishing trust material — the adapter and Deployment do not change.

Brownfield adapter

In front of an unmodified API

A reverse-proxy verifier that returns clear allow / 401 / 403 outcomes before traffic reaches the upstream service.

Broker

Local issuance, optional SPIFFE

A local broker issues request-bound passports and can require SPIFFE/SPIRE attested workload identity on Kubernetes.

Audit events

Stable decision records

A stable JSON record of every allow/deny with caller, route, policy, and reason — useful for review and incidents.

Local-first by design

Decisions happen in your infrastructure.

Auth verifies using local trust material and policy during request handling. It works offline, with no account, database, or hosted bundle source required to run — so sensitive request traffic never has to leave your environment.

No mandatory phone-home

The verifier does not depend on a hosted service at request time; trust and policy are mounted locally.

Works with your identity

Use SPIFFE/SPIRE, OIDC/JWT, or a local issuer — Auth adds request-bound proof on top.

Kubernetes optional

Runs as local processes, on VMs, at the edge, and in CI. SPIFFE/SPIRE is recommended, not required.

Caller SDKs

Sign proof-bound requests from Go and Node.js (TypeScript); a Python SDK is planned.

Open standards

Built on identity, not in place of it.

TrustPlane Auth doesn't reinvent identity, and it doesn't want to replace your IdP. It consumes SPIFFE/SPIRE and OIDC/JWT, and applies the request-bound, proof-of-possession model the IETF is standardizing through DPoP (RFC 9449), the WIMSE working group, and OAuth Transaction Tokens — pointed at the place that has been ignored: agents and machine systems.
