TrustPlane is an authorization plane for AI agents, MCP servers, and machine-to-machine traffic. TrustPlane Auth verifies a short-lived, request-bound passport for each machine request inside your infrastructure. TrustPlane Control governs enrollment, policy releases, revocation, and audit across the fleet. Control centrally, enforce locally.

The problem

The questions your next security review will ask.

Machine traffic already outnumbers human traffic in most stacks. The review questions haven't changed — they've just become unanswerable with static keys.

“What can this agent actually do?”An agent can be useful, fast, and wrong in the same minute. A bearer token answers “who it claims to be,” not “what this specific request is allowed to change.”
“Where are the keys?”In config, in logs, in prompts, in CI, in a partner's environment. Rotation is cleanup after the fact. It doesn't make the next request trustworthy.
“How fast can you revoke?”When a workload misbehaves, you need one place that removes its authority everywhere — without redeploying services or hunting down copies of a secret.
“Show me the evidence.”Auditors and incident responders want the same artifact: what called what, which policy version applied, and why the decision went the way it did.
The platform

Two products. One operating model for machine trust.

SPIFFE authenticates workloads. TrustPlane Passport authenticates requests. Auth enforces at the boundary; Control governs the fleet.

TrustPlane Auth · free to run

Verify every request where it lands

Auth issues and verifies short-lived passports — proof-bound authorization artifacts derived from workload identity. Verification is local: keys resolve from signed trust bundles on disk, so there's no per-request round trip to anyone, including us.

  • Seven checks per request, including replay protection
  • Brownfield adapter: protect an existing HTTP service without code changes
  • Go middleware, local issuer and verifier binaries, CLI
  • Fails closed, with a clear deny reason every time

Architecture

Control centrally. Enforce locally.

Your request traffic never routes through our cloud. Control signs and distributes policy and trust material; Auth verifies against local copies. If Control is unreachable — or your contract lapses — enforcement keeps running exactly as configured.

Straight answers

Promises we're comfortable putting in writing.

Security products earn trust by being boring about the important things. These behaviors are contracts in the product, not aspirations on a slide.

Billing never touches the request path.

Authorization decisions read policy and trust material — never subscription state. A payment failure can block new activations; it can never switch off a running Auth Site, anchor, or client.

No surprise stops. Ever.

Cancel and walk away, and everything you enrolled keeps enforcing your last policy. We compete on being useful, not on holding your runtime hostage.

Verification works offline.

Issuer keys resolve from signed local bundle documents. An Auth verifier makes the same decision with or without a network path to anything.

Unknown means no.

Missing trust material, an unsupported proof profile, an unrecognized route: the verifier fails closed and tells you why in the deny reason.

FAQ

What is TrustPlane? Short answers, no hedging.

What is AI agent authorization?

AI agent authorization is deciding, per request, whether an autonomous or semi-autonomous software actor may perform a specific action — and producing evidence of that decision. It differs from authentication, which only establishes identity. TrustPlane implements it with short-lived, request-bound passports verified inside your infrastructure.

Is TrustPlane an identity provider?

No. TrustPlane consumes identity from OIDC/JWT issuers, SPIFFE/SPIRE, or TrustPlane-native issuers, and adds request-level authorization on top. Your human IdP stays exactly where it is.

Do I need Kubernetes?

No. TrustPlane is Kubernetes-compatible, not Kubernetes-dependent. The adapter and middleware run anywhere Go binaries run.

Do I need Control to start?

No. Develop is free and self-contained: run Auth, protect a service, see decisions. Control matters when the fleet grows — when enrollment, policy rollout, revocation, and audit become someone's job.

Who builds TrustPlane?
