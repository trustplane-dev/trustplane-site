Why now

Software is becoming an operator. Bearer access was not built for that.

Agents expand your attack surface.An agent can be useful, fast, and wrong in the same minute. Authorization has to be tied to what it is doing, not only who it says it is.
Machine credentials sprawl quietly.Keys and tokens land in config, logs, prompts, notebooks, CI, and partner environments. Rotation helps after the fact. It does not make each request trustworthy.
Audit needs request-level evidence.Security reviews ask the same questions: what called what, why was it allowed, what policy version applied, and how fast can we revoke it?
Platform

Two products, one operating model for machine trust.

Keep enforcement close to the API. Govern enrollment, policy, revocation, and audit from the control plane.

TrustPlane Auth

Runtime authorization at the boundary

Auth sits in the request path and verifies machine traffic before it reaches the protected service. It is built for local enforcement, clear deny reasons, and integration with the infrastructure teams already run.

  • Request-aware verification for agent and service calls
  • Gateway, sidecar, and service-adjacent deployment patterns
  • Local decisions with audit events for each allow or deny

TrustPlane Control

Govern access across fleets and teams

Control is where platform and security teams manage trust anchors, enrollment, policy releases, revocation, environments, and audit without editing every service or redistributing static credentials.

  • Central policy and signed distribution to Auth deployments
  • Fleet visibility, environment separation, and operator roles
  • Managed and enterprise self-hosted deployment paths

FAQ

Short answers for security and platform teams.

Is TrustPlane an identity provider?

No. TrustPlane focuses on authorization for machine and agent traffic. It is designed to work with identity systems and infrastructure patterns teams already use.

Where does enforcement happen?

TrustPlane Auth enforces close to the protected API or service, inside your infrastructure. TrustPlane Control manages the policies and operational state across the fleet.

Who is the first buyer?

Security engineering, platform engineering, infrastructure, and product teams shipping agentic or machine-to-machine workflows where static credentials are becoming a blocker.

Is Control required to start?

No. The preview is structured so teams can begin with Auth and docs, then add Control when fleet governance, policy distribution, revocation, and enterprise audit become necessary.
