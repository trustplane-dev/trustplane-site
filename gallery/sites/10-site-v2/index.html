The problem

A long-lived token is standing authority. Hand one to an autonomous agent and a single leak — or one prompt injection — authorizes every call it can reach.

Presented, not proven

API keys and bearer tokens grant access by mere possession. Whoever holds the string is the client — from anywhere, until it's rotated.

Not bound to the request

A token that may read /orders can be replayed against /admin the moment anything slips. The credential authorizes the actor, never the action.

Invisible after the fact

Keys leak into code, logs, and prompts. Without per-request proof there is no way to tell a legitimate call from a hijacked one.

How it works

Prove the request. Don't present a secret.

Trustplane turns a workload's existing identity into a short-lived, request-bound credential — verified locally, with no phone-home.

01

Identity

Start from SPIFFE/SPIRE or OIDC/JWT. No static secret to store or leak.

02

Proof

Sign a proof bound to the exact method, path, body and time of this call.

03

Verify

The adapter checks signature, audience, binding and policy — then consumes the proof once.

04

Audit

Every allow/deny decision is recorded and tied to the request it bound.

Request-bound proofs, not standing tokens

Each call carries a proof tied to its parameters. Tamper the path or replay the proof and verification fails closed — so a compromised or injected agent can't act beyond the call it was authorized for.

# sign one specific call
$ trustplane sign --method GET --path /orders \
    --audience acme.orders
✓ allow   verified · single-use · audited

# replay the same proof?
✗ deny    jti_replay
# tamper the path after signing?
✗ deny    request_binding_mismatch

A drop-in boundary, no rewrite required

A reverse-proxy adapter verifies requests in front of your existing API, in your own infrastructure. Add a new caller by publishing trust material — no code change, no adapter redeploy. Kubernetes-compatible, never Kubernetes-required.

Where Trustplane fits

Built for machine and agent traffic.

AI agents calling internal & external APIs

Authorize first-party and third-party agents without issuing long-lived API keys. Every request carries verifiable identity and request proof.

Provider-managed APIs for machine clients

Enforce per-request authorization at your own boundary without rewriting upstream APIs or managing shared credentials per caller.

Service-to-service authorization

Replace internal API keys with request-level proofs. Every service-to-service call is verifiable, auditable, and replay-protected.

Cross-organization machine access

Partner machine clients enroll through trust anchors. Authorization is cryptographic — not trust-on-first-use.

Open standards

Built on identity, not in place of it.

Trustplane doesn't reinvent identity. It consumes SPIFFE/SPIRE and OIDC/JWT, and implements the proof-of-possession, request-bound model the IETF is converging on through DPoP, WIMSE workload identity & proof tokens, and OAuth Transaction Tokens — applied today to agents and machine systems.
