TrustPlane Auth is a free-to-run authorization runtime for machine and AI-agent traffic. It issues and verifies TrustPlane Passports — short-lived, proof-bound artifacts derived from workload identity — and applies local policy before a request reaches the protected service. Verification is offline-capable by construction.

The distinction

A key states who you are. A passport states what this request may do.

i

Authority that expires

Passports live for seconds to minutes, not quarters. A leaked passport is a diminishing problem; a leaked API key is a standing appointment.

ii

Authority that is bound

The proof covers the request at hand — route, method, audience — so no grant quietly stretches to actions nobody approved in writing.

iii

Authority that cannot repeat

Replay tracking denies the second presentation of any passport. A recorded request cannot be resubmitted as a second refund.

Adoption

Three doors in. None requires a renovation.

1

The adapter, for standing services

A verifier-forwarding proxy placed before an existing HTTP service, in any language. Requests that fail verification never arrive; the service is not edited, recompiled, or informed.

2

Middleware, for Go services

In-process HTTP middleware and reverse-proxy primitives, for teams that prefer verification within the service boundary itself.

3

Gateway and sidecar patterns

Verification at the API edge, beside workloads, or before MCP and tool servers. Kubernetes-compatible; never Kubernetes-dependent.

Questions of record

Auth, examined.

Free to run — where is the catch?

The catch is candid: when your fleet grows, enrollment, signed policy rollout, revocation, and audit will deserve one governed home. That is Control, and it is the product we sell.

What does “proof-bound” mean in practice?

Each passport carries a confirmation claim binding it to the presenting client and the intended request context. Verification examines that binding along with signature, issuer, audience, expiry, trust domain, and replay state — seven checks per decision.

How does policy reach the verifier?

On Develop, signed trust-material and policy bundles are placed as local files. Under Control, the same artifacts are versioned, signed, and distributed to your Auth Sites; revocation travels the same road.

Which languages are supported?

The runtime and middleware are Go. The adapter protects services written in anything, as it operates at the HTTP boundary.
